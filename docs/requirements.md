# Paper-Reading-Agent 项目需求文档

## 1. 项目名称

Paper-Reading-Agent

一个面向科研论文阅读、知识梳理和后续学习规划的本地 AI Agent。用户输入或导入一篇论文后，系统辅助用户理解论文结构、核心问题、方法贡献、关键术语和后续学习路径，并支持基于论文内容的可追溯问答。

## 2. 目标用户

- AI、计算机科学、数据科学等方向的本科生、研究生和科研新人。
- 需要快速理解论文内容、整理阅读笔记的科研工作者。
- 正在进入某个新研究方向，希望通过论文建立系统学习路径的学习者。
- 需要把论文内容转化为汇报材料、学习任务或复习资料的用户。

## 3. 当前版本范围

当前版本是本地 MVP，不追求一次性完成完整论文智能体，而是优先建立稳定的数据流和模块边界：

- 支持手动输入论文标题、摘要和 Markdown 正文。
- 支持 Markdown 章节解析和文本分块。
- 支持结构化分析结果和 Markdown 阅读笔记落盘。
- 支持基于 chunks 的最小论文问答。
- 支持前端完成分析和问答闭环。
- 支持 pytest 自动化测试。

当前版本尚未实现：

- PDF 文件解析。
- 论文链接抓取。
- 真实 LLM 调用。
- 向量检索。
- CLI 命令行入口。
- 多论文库和历史记录。

## 4. 输入需求

### 4.1 当前已支持输入

- 论文标题：用于展示、生成 `paper_id` 和后续元数据管理。
- 论文摘要：用于占位 LLM 总结和阅读笔记。
- Markdown 正文：用于保存原文、解析章节、生成 chunks 和论文问答。
- 用户问题：通过 `/api/papers/{paper_id}/ask` 围绕当前论文提问。

### 4.2 规划中的输入

- 本地 PDF 文件。
- 论文链接：arXiv、OpenReview、ACL Anthology、GitHub README、会议论文页面等公开链接。
- 用户背景：专业方向、已有知识水平、当前学习目标。
- 阅读目标：快速扫读、精读、复现论文、准备组会汇报、写相关工作综述等。
- 时间约束：例如 30 分钟快速理解、3 天精读、一周复现。
- 输出偏好：中文或英文、简要或详细、Markdown 笔记、表格、学习清单等。

## 5. 输出需求

### 5.1 当前已支持输出

- 结构化 JSON 分析结果：
  - `paper_id`
  - `source`
  - `sections`
  - `chunks`
  - `summary`
  - `learning_plan`
  - `glossary`
  - `artifacts`
- Markdown 阅读笔记：
  - 基本信息
  - 摘要
  - 论文总结
  - 章节结构
  - 术语表
  - 学习计划
  - 文件位置
- 问答结果：
  - `question`
  - `answer`
  - `citations`
  - 引用 chunk 的章节、正文和关键词命中分数。

### 5.2 规划中的输出

- 由真实 LLM 生成的一页纸论文总结。
- 更细粒度的研究问题、方法、贡献、实验、结论和局限性分析。
- 基于引用片段生成的自然语言答案。
- 学习计划 Markdown 文件。
- 术语表独立文件。
- 问答历史记录文件。
- 多论文对比和综述结果。

## 6. 功能需求

### 6.1 文档输入与解析

当前状态：

- 支持 Markdown 正文输入。
- 保存原始 Markdown 到本地工作区。
- 支持解析 `#` 到 `######` 标题。
- 支持正文分块，生成 `chunks.json`。

后续目标：

- 支持本地 PDF 文件输入。
- 从 PDF 中提取标题、摘要、章节、正文、参考文献和页码。
- 对长文档进行更精确的按章节分块。
- 为每个 chunk 记录章节、页码、段落位置等来源信息。

### 6.2 论文内容理解

当前状态：

- 已定义 `LLMClient` 模型调用边界。
- 当前返回占位总结、占位术语表和占位学习计划。
- 分析结果通过 Pydantic schema 固定结构。

后续目标：

- 接入真实 LLM API。
- 生成论文的一页纸总结。
- 提取研究问题、核心方法、主要贡献、实验设置、关键结果和局限性。
- 识别论文中的关键术语，并生成术语解释。

### 6.3 基于论文的问答

当前状态：

- 用户可以围绕当前论文提问。
- 系统读取该论文的 `chunks.json`。
- `KeywordRetriever` 使用关键词命中检索相关片段。
- 返回模板化答案和引用片段。

后续目标：

- 使用向量检索提升语义匹配能力。
- 使用 LLM 基于检索片段生成自然语言答案。
- 回答中标注章节、页码、chunk id 和原文片段。
- 保存问答历史。

### 6.4 学习规划生成

当前状态：

- `LLMClient` 中保留学习计划生成接口。
- 阅读笔记中包含学习计划区域。

后续目标：

- 根据论文主题生成前置知识清单。
- 根据用户阅读目标生成阶段性学习任务。
- 输出简洁可执行的 Markdown 学习计划。
- 根据用户背景调整解释深度。

### 6.5 前端界面

当前状态：

- 原生 HTML/CSS/JavaScript 页面。
- 支持后端健康检查。
- 支持提交论文分析请求。
- 支持展示结构化分析结果。
- 支持基于当前 `paper_id` 的论文问答。
- 支持展示问答引用片段。

后续目标：

- 支持论文文件上传。
- 支持论文历史记录。
- 支持论文原文和 AI 笔记并排阅读。
- 支持高亮引用片段并跳转到原文位置。
- 根据复杂度决定是否升级为 React 或 Vue。

## 7. 非功能性要求

- 可解释性：问答必须尽量给出来源位置，避免无依据总结。
- 可测试性：核心解析、分块、检索、服务编排和 API 都应有测试覆盖。
- 可复用性：解析、检索、问答、笔记生成和学习规划模块保持清晰边界。
- 本地优先：MVP 优先支持本地文件和本地缓存，降低部署复杂度。
- 可扩展性：后续应方便接入真实 LLM、Web UI、多论文库、长期记忆和不同模型服务。
- 输出稳定性：生成的 JSON 和 Markdown 文件结构应固定，便于用户复习和后续程序处理。
- 可追溯性：问答和总结应逐步增加 chunk id、章节、页码等来源字段。

## 8. 技术选型

### 8.1 当前已使用

- Python：后端主要开发语言。
- FastAPI：API 服务。
- Pydantic：请求、响应和内部结构化数据模型。
- pytest：单元测试和接口测试。
- FastAPI TestClient：API 测试。
- 原生 HTML/CSS/JavaScript：前端 MVP。
- 本地文件系统：运行期数据存储。

### 8.2 后续候选

- OpenAI API 或兼容 OpenAI 协议的大模型 API：摘要、问答、术语解释和学习规划生成。
- PyMuPDF 或 pdfplumber：解析 PDF 文本、页码和基础版面信息。
- FAISS 或 Chroma：本地向量检索。
- SQLite：保存论文元数据、任务记录和用户配置。
- Typer 或 argparse：实现 CLI。
- ruff：代码检查和格式化。
- mypy：可选静态类型检查。
- GitHub Actions：自动化测试。

## 9. 当前 MVP 使用流程

1. 启动 FastAPI 后端。
2. 打开前端 `frontend/index.html`。
3. 输入论文标题、摘要和 Markdown 正文。
4. 前端调用 `/api/papers/analyze`。
5. 后端保存原文、解析章节、生成 chunks、保存分析产物和阅读笔记。
6. 前端展示分析结果，并保存当前 `paper_id`。
7. 用户围绕当前论文提问。
8. 前端调用 `/api/papers/{paper_id}/ask`。
9. 后端读取 `chunks.json`，通过关键词检索返回答案和引用片段。

## 10. 后续迭代优先级

1. 优化 chunking，使 chunk 精确绑定章节，避免所有片段都归到首个 section。
2. 增加问答历史落盘。
3. 接入真实 LLM，将模板化回答升级为基于引用片段的生成式回答。
4. 增加 PDF 解析。
5. 引入 SQLite 管理论文元数据。
6. 引入向量检索。
7. 扩展前端为完整阅读工作台。
