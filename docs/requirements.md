# Paper-Reading-Agent 项目需求文档

## 1. 项目名称

Paper-Reading-Agent

一个面向科研论文阅读、知识梳理和后续学习规划的 AI Agent。用户上传或指定一篇论文后，系统自动解析论文内容，辅助用户理解论文结构、核心贡献、关键方法、实验结果，并生成可执行的学习计划。

## 2. 目标用户

- AI、计算机科学、数据科学等方向的本科生、研究生和科研新人。
- 需要快速理解论文内容、整理阅读笔记的科研工作者。
- 正在进入某个新研究方向，希望通过论文建立系统学习路径的学习者。
- 需要把论文内容转化为汇报材料、学习任务或复习资料的用户。

## 3. 输入是什么

### 3.1 核心输入

- 论文文件：PDF 或 Markdown 格式。
- 论文链接：arXiv、OpenReview、ACL Anthology、GitHub README、会议论文页面等公开链接。
- 用户问题：针对论文内容提出的自然语言问题，例如“这篇论文的主要贡献是什么？”、“实验设置是否合理？”、“我需要补哪些基础知识？”。

### 3.2 可选输入

- 用户背景：专业方向、已有知识水平、当前学习目标。
- 阅读目标：快速扫读、精读、复现论文、准备组会汇报、写相关工作综述等。
- 时间约束：例如 30 分钟快速理解、3 天精读、一周复现。
- 输出偏好：中文或英文、简要或详细、Markdown 笔记、表格、学习清单等。

## 4. 输出是什么

### 4.1 基础输出

- 论文摘要：用更易理解的语言总结论文研究问题、方法、实验和结论。
- 结构化阅读笔记：按照背景、问题、方法、贡献、实验、局限性等维度整理。
- 术语表：提取论文中的关键概念、缩写、公式符号，并给出解释。
- 问答结果：基于论文内容回答用户提出的问题，并尽量引用对应章节或段落。
- 学习规划：根据论文内容和用户背景生成后续学习任务。

### 4.2 学习规划输出

- 前置知识清单：阅读该论文需要补充的基础概念、数学知识、模型结构或工程知识。
- 学习任务列表：按优先级拆解为可执行任务，例如阅读相关博客、查阅综述、理解某个模型模块、复现实验。
- 时间安排：根据用户可用时间生成短期学习计划。
- 延伸阅读建议：给出相关论文、关键词或研究方向。

### 4.3 文件输出

- Markdown 阅读笔记。
- Markdown 学习计划。
- 可选的术语表文件。
- 可选的问答记录文件。

## 5. 最小功能

### 5.1 文档输入与解析

- 支持本地 PDF 文件输入。
- 支持 Markdown 文本输入。
- 从论文中提取标题、摘要、章节、正文、参考文献等基础结构。
- 对长文档进行分块，便于后续检索和问答。

### 5.2 论文内容理解

- 生成论文的一页纸总结。
- 提取研究问题、核心方法、主要贡献、实验设置、关键结果和局限性。
- 识别论文中的关键术语，并生成术语解释。

### 5.3 基于论文的问答

- 用户可以围绕当前论文提问。
- 系统基于论文内容检索相关片段并生成回答。
- 回答中标注信息来源，例如章节名、页码或文本片段。

### 5.4 学习规划生成

- 根据论文主题生成前置知识清单。
- 根据用户阅读目标生成阶段性学习任务。
- 输出一个简洁可执行的 Markdown 学习计划。

### 5.5 命令行入口

- 提供 CLI 命令运行最小流程。
- 用户可以指定论文路径、输出目录和输出语言。
- 运行后在指定目录生成阅读笔记与学习计划。

## 6. 后续可扩展功能

### 6.1 多论文管理

- 支持导入多篇论文，建立本地论文库。
- 支持按主题、作者、会议、年份、标签管理论文。
- 支持跨论文检索、对比和综述生成。

### 6.2 论文关系与研究脉络

- 自动分析引用关系和被引用关系。
- 生成相关工作图谱。
- 对比同一方向多篇论文的方法差异、实验差异和贡献边界。

### 6.3 个性化学习系统

- 记录用户已读论文、掌握概念和历史问题。
- 根据用户水平动态调整解释深度。
- 生成长期学习路线，例如“4 周入门 RAG 论文阅读路线”。

### 6.4 复现辅助

- 提取论文中的实验配置、数据集、指标和训练细节。
- 识别论文是否提供代码仓库。
- 生成复现 checklist。
- 辅助阅读源码并解释模型实现。

### 6.5 前端界面

- 提供 Web UI 上传论文、查看笔记、提问和管理学习计划。
- 支持论文原文与 AI 笔记并排阅读。
- 支持高亮引用片段和跳转到原文位置。

### 6.6 知识库与记忆

- 使用向量数据库保存论文分块和用户笔记。
- 支持长期记忆用户偏好和学习进度。
- 支持从历史论文中检索相关知识。

### 6.7 多模态理解

- 解析论文中的图表、公式和算法伪代码。
- 对图表生成解释。
- 将复杂公式转化为文字说明和学习提示。

## 7. 技术栈

### 7.1 后端与 Agent 框架

- Python：主要开发语言。
- LangChain 或 LlamaIndex：用于文档解析、分块、检索增强生成和 Agent 编排。
- OpenAI API 或兼容 OpenAI 协议的大模型 API：用于摘要、问答、术语解释和学习规划生成。

### 7.2 文档解析

- PyMuPDF 或 pdfplumber：解析 PDF 文本、页码和基础版面信息。
- Markdown 解析库：处理 Markdown 格式论文或笔记。
- 可选 GROBID：用于更精细地解析学术论文结构和参考文献。

### 7.3 检索与存储

- FAISS 或 Chroma：本地向量检索。
- SQLite：保存论文元数据、任务记录和用户配置。
- 本地文件系统：保存生成的 Markdown 笔记、学习计划和缓存文件。

### 7.4 命令行与配置

- Typer 或 argparse：实现 CLI。
- Pydantic：管理配置、输入参数和结构化输出。
- python-dotenv：管理 API Key 等环境变量。

### 7.5 前端扩展

- FastAPI：提供后端 API。
- React 或 Vue：构建 Web UI。
- Tailwind CSS：快速实现简洁的界面样式。

### 7.6 测试与工程化

- pytest：单元测试和集成测试。
- ruff：代码检查和格式化。
- mypy：可选的静态类型检查。
- GitHub Actions：后续用于自动化测试。

## 8. MVP 使用流程

1. 用户准备一篇 PDF 或 Markdown 论文。
2. 用户通过 CLI 指定论文路径和输出目录。
3. 系统解析论文并进行分块。
4. 系统生成论文总结、结构化阅读笔记和术语表。
5. 系统根据论文主题生成后续学习计划。
6. 用户针对论文继续提问，系统基于论文内容回答。

## 9. 非功能性要求

- 可解释性：回答应尽量给出来源位置，避免无依据总结。
- 可复用性：解析、检索、问答、笔记生成和学习规划模块应保持清晰边界。
- 本地优先：MVP 优先支持本地文件和本地缓存，降低部署复杂度。
- 可扩展性：后续应方便接入 Web UI、多论文库、长期记忆和不同大模型服务。
- 输出稳定性：生成的 Markdown 文件结构应固定，便于用户复习和后续程序处理。
